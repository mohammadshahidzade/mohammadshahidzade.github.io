01 / MOTIVATION

Make FPGA acceleration accessible from the model level.

Deploying a neural network on an FPGA crosses many boundaries: model representation, quantization, layer scheduling, buffer sizing, RTL generation, SoC integration, and host software. A useful builder has to connect those layers rather than optimize one in isolation.

This project grew from experience with CFU-Playground and TensorFlow Lite Micro. Instead of placing a tightly coupled accelerator inside the CPU datapath, the design used an external streaming architecture to improve memory access and support larger accelerator structures.

02 / MY CONTRIBUTION

Extending the flow in both directions.

PyTorch modelLayer loweringStreaming RTLLiteX SoCFPGA
  • Added support for additional neural-network layer types so more complete models could pass through the builder.
  • Built a PyTorch-facing workflow to extract model structure and parameters for accelerator generation.
  • Developed and adapted streaming Verilog modules for layer execution and data movement.
  • Integrated the generated accelerator into LiteX, connecting it to the processor, memory system, and FPGA build flow.
  • Worked across model software, generated metadata, hardware interfaces, and board-level validation.
03 / DESIGN VALUE

A full-stack project changes how each layer is designed.

Model support is not only a software-parser problem: every added layer changes buffering, control, data layout, and resource use. Likewise, an RTL block is only useful when the host can configure it and the SoC can feed it efficiently. This project developed practical experience across that entire chain.
